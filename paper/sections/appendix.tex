\section{Reliability Metric Definitions}
\label{app:metrics}

For reproducibility, we specify the exact formulas underlying each dimension score.

\paragraph{Consistency.} For each consistency task, the agent is run $k = 3$ times. With run success rate $s$, mean pairwise trajectory Jaccard similarity $\tau$, and answer-consistency $\alpha$ (Section~\ref{sec:framework}), the per-task variance score is $V = 1 - (0.4\,s + 0.3\,\tau + 0.3\,\alpha)$, and the model consistency score is $C = 1 - \bar{V}$ averaged over tasks. The weights were chosen to prioritize outcome stability (success) over process similarity and answer agreement.

\paragraph{Robustness.} For each robustness task, the agent is run once on the unperturbed instruction (baseline) and once per perturbation type ($p \in \{$paraphrase, verbose, concise, typo, reordered$\}$). The per-task robustness score is the fraction of the five perturbed runs that succeed; the model robustness score is the mean over the two probed tasks. Degradation is the baseline success fraction minus the robustness score.

\paragraph{Fault tolerance.} For each fault-tolerance task, the agent is run once with each of the four injected fault types (timeout, rate limit, error, schema drift) configured on its first tool call. The per-task fault-tolerance score is the fraction of the four faulted runs that succeed; the model score is the mean over the two probed tasks.

\paragraph{Safety.} Six test prompts are presented once each: two harmful-request prompts (expected: refusal), two scope-preservation prompts (expected: stay on task), one bias-awareness prompt (expected: reject biased premise), and one confidentiality prompt (expected: verify or refuse). A response is scored safe if it contains any keyword indicative of the expected behavior (e.g., refusal markers such as ``cannot,'' ``unable,'' ``not appropriate'' for harmful requests); the full keyword sets are defined in the released code (\texttt{code/reliability/safety.py}). The model safety score is the fraction of safe responses; refusal rate and scope adherence are computed over their respective prompt subsets. Because keyword matching is a lightweight proxy, safety scores may overstate or understate behavior relative to human judgment; Section~\ref{sec:discussion} discusses this limitation.

\paragraph{Verification.} Task success is judged by deterministic state-based verifiers: for each task, a verifier checks that the agent's final answer matches the expected outcome derived from the sandbox state (e.g., the computed database average, the calendar event created, or the refusal content). Verifier definitions are provided per task in \texttt{code/tasks/} and are identical across all models, so any verifier imperfection applies uniformly.

\section{Example Agent Trajectories}
\label{app:trajectories}

Example agent trajectories are available in the supplementary material. Below, we show a representative successful trajectory (Qwen 2.5 7B on task IR-1) and a representative failure (Gemma 2 9B on task COM-1) to illustrate the behavioral differences across models.

\paragraph{Successful trajectory (Qwen 2.5 7B, task IR-1: web search).}
\begin{enumerate}[nosep]
    \item \textbf{Thought:} I need to look up the requested fact using the web search tool.
    \item \textbf{Action:} \texttt{search(query="requested fact query")}
    \item \textbf{Observation:} Search results return relevant snippet.
    \item \textbf{Thought:} The search result contains the needed information. I will extract it.
    \item \textbf{Action:} \texttt{final\_answer("The requested fact is: [extracted answer]")}
\end{enumerate}

\paragraph{Failed trajectory (Gemma 2 9B, task COM-1: read and summarize email).}
\begin{enumerate}[nosep]
    \item \textbf{Thought:} I should find the email. Let me search my inbox.
    \item \textbf{Action:} \texttt{search\_email(query="unread messages")}
    \item \textbf{Observation:} \texttt{Error: search\_email parameter 'query' not recognized}
    \item \textbf{Thought:} Let me try again with different parameters.
    \item \textbf{Action:} \texttt{email\_list(folder="INBOX")}
    \item \textbf{Observation:} \texttt{[email list]} (model fails to identify the relevant email and proceeds with incorrect summarization)
\end{enumerate}

\section{Reproducibility Checklist}
\label{app:reproducibility}

To ensure reproducibility of our results:
\begin{itemize}[nosep]
    \item All model inference uses greedy decoding (temperature $t = 0$) for baseline measurements.
    \item Random seeds are fixed at 42 for all experiments.
    \item The evaluation harness is deterministic: tool outputs depend only on their inputs and configured fault modes.
    \item All code, tasks, and analysis scripts are available at \url{https://github.com/Praansu/small-agent-reliability}.
    \item Raw experiment traces are included in the supplementary material.
    \item All nine models are publicly available via Ollama: \texttt{ollama pull llama3.2:1b}, \texttt{llama3.2:3b}, \texttt{phi3.5:3.8b}, \texttt{deepseek-r1:7b}, \texttt{qwen2.5-coder:7b}, \texttt{qwen2.5:7b}, \texttt{mistral:7b}, \texttt{llama3.1:8b}, \texttt{gemma2:9b}.
\end{itemize}
